# TASK-0003: Emit data/word-bank.json

## Summary

Extend the `--csv` build to also write a typed, versioned
`data/word-bank.json` containing every bank word with its game-letter count and
possible syllable counts. The CSV remains for human review; the JSON becomes the
API's source of truth.

## Context

The API needs structured values (`letters`, `syllables` array, `needsReview`).
Parsing `data/word-bank.csv` on every boot is fragile because cells can be
quoted and the format is intended for humans. The existing build already
computes exactly the needed fields in `buildCsv()` in `main.js`.

`data/` is gitignored, so the artifact is generated by `node main.js --csv`
after a `--sync`.

## Scope

### In scope

- Extract the bank-building and rendering logic into `lib/buildBank.js`:
  - `buildWordBank(words, options)` → a plain object.
  - `renderCsv(bank)` → the existing CSV text.
  - `renderWordList(bank)` → the existing newline-separated word list.
- JSON shape:

  ```json
  {
    "schemaVersion": 1,
    "generatedAt": "2026-10-21T12:00:00.000Z",
    "wordCount": 24134,
    "maxLetters": 9,
    "words": [
      {
        "word": "abadi",
        "letters": 5,
        "syllables": [3],
        "needsReview": false
      }
    ]
  }
  ```

- `buildWordBank` accepts an injected clock (`now`) for deterministic tests.
- Words are sorted lexicographically and unique.
- `syllables` is always an ascending numeric array; `needsReview` is
  `syllables.length > 1`.
- Write the JSON compactly with `JSON.stringify(bank)` to keep the artifact
  small.
- Update `buildCsv()` in `main.js` to use the new module and write
  `data/word-bank.json`.
- Preserve the existing console summary counts.
- Update the README files table and CSV section to mention the JSON artifact.
- Add `test/buildBank.test.js`.

### Out of scope

- Changing bank filters (spaces, `MAX_GAME_LETTERS`, three-syllable rule).
- Loading the artifact at runtime (TASK-0004).
- HTTP code.

## Acceptance Criteria

- [ ] `node main.js --csv` writes `data/word-bank.csv`,
  `data/words-3syllables.txt`, and `data/word-bank.json`.
- [ ] The CSV header and column order are unchanged.
- [ ] `wordCount` equals the number of JSON entries and the CSV row count.
- [ ] Every JSON word has `letters <= 9`, no spaces, and `3` in `syllables`.
- [ ] `needsReview` is true exactly when more than one syllable count is
  possible.
- [ ] Tests pass with an injected fixed timestamp, so output is deterministic.

## Implementation Plan

1. Create `lib/buildBank.js`. Move the filtering loop from `buildCsv()`.
   Keep counters for spaces, over-length, not-three, and ambiguous words;
   return them alongside the bank for logging.
2. Implement `renderCsv` and `renderWordList` using the bank entries so all
   three artifacts are derived from one in-memory structure.
3. Replace the body of `buildCsv()` with:
   - `loadWordList(WORDS_FILE)`
   - `buildWordBank(words)`
   - three `writeArtifact` calls
   - the existing summary lines
4. Add `JSON_FILE = path.join(__dirname, 'data', 'word-bank.json')`.
5. Add tests:
   - Filters spaces, over-length words, and words without 3 syllables.
   - Ambiguous diphthong words get multiple counts and `needsReview: true`.
   - Sorting and uniqueness.
   - CSV and plain-list renderers match the old format.
6. Update the README files table.
7. Open a PR using branch `feat/0003-word-bank-json`, link it in the Status Log,
   and request one reviewer.

## Risks

- **Artifact size:** ~24k entries can reach 1–2 MB. Mitigation: compact JSON,
  no pretty printing, and keep the file out of git.
- **Non-determinism:** `generatedAt` changes every build. Mitigation: inject
  the clock in tests and never compare raw JSON bytes in CI.
- **Behavior drift in filtering:** moving the loop can accidentally change
  counters or ordering. Mitigation: keep the original conditions and add
  parity tests against the CSV rows.
- **Stale artifacts:** the CSV and JSON are only updated together by
  `--csv`. Document that `--sync` alone is not enough.

## Dependencies

- TASK-0002 (new `lib/` layout and error types).

## Rollout/Backout Plan

The new artifact is additive. If it causes problems, delete
`data/word-bank.json` and revert the commit; the CLI and CSV continue to work.
No migration is required.
